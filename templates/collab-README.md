# human 지시 사항 및 결과 파일 모음

이 폴더는 이 프로젝트에서 **인간과 AI가 협업하는 단일 인터페이스**다. 인간은 이 폴더만 보면 전체 작업을 파악할 수 있어야 한다.

## 구조

```
human 지시 사항 및 결과 파일 모음/
├── README.md
├── input_by_human/
│   ├── _요청_템플릿/                          # `_` 시작 작업 폴더 = 연번 제외
│   │   └── request.md
│   └── _공통/                                 # 그룹 폴더 (= 작업 갈래)
│       └── 20260826_01_협업폴더-구조개선/
│           ├── request.md                    # 요청 본문 (진입점)
│           └── (참고 소스: 이미지·CSV·기존 문서)
└── output_from_AI/
    └── _공통/                                 # input과 글자 단위로 동일한 구조
        └── 20260826_01_협업폴더-구조개선/
            ├── 00_요약.md                     # 산출물 진입점
            └── (산출물)
```

작업 갈래가 여러 개면 그룹 폴더를 늘린다. 연번은 그룹마다 따로 돈다:

```
input_by_human/
├── _공통/
│   └── 20260826_01_협업폴더-구조개선/
├── lm-site-audit/
│   ├── 20260902_01_스킬설계/
│   └── 20260902_02_리스닝마인드-1회차/
└── lm-onpage-seo/
    ├── 20260902_01_스킬설계/                  # 그룹이 다르므로 01이 겹쳐도 된다
    └── 20260902_02_리스닝마인드-1회차/
```

## human-AI 협업 규칙 (collab-init v3)

### 1. 작업 쌍은 그룹 폴더 안에 있다

`input_by_human/`과 `output_from_AI/` 바로 아래는 **그룹 폴더**다. 작업 쌍은 반드시 그룹 폴더 안에 있고, 트리 바로 아래에 작업 폴더를 두지 않는다. 한 갈래의 작업들이 다른 갈래 사이에 섞여 흩어지는 걸 막기 위해서다.

- 그룹 = 이 프로젝트의 **작업 갈래(트랙)**. 나눌 게 없으면 기본 그룹 `_공통/` 하나만 쓴다. 나중에 갈래가 생기면 그때 그룹을 추가한다.
- 그룹 이름은 그 갈래를 부르는 이름 그대로 짧게 쓴다. 산출물이 특정 대상에 귀속되는 프로젝트라면 그 대상 이름을 그대로 쓰는 게 가장 헷갈리지 않는다.
  - 스킬을 만드는 프로젝트 → 스킬 디렉터리 이름 (`lm-site-audit`)
  - 제품·클라이언트가 여럿인 프로젝트 → 제품·클라이언트 이름
  - 그 외 → `리서치`, `배포`처럼 갈래 이름
- 어느 갈래에도 안 붙는 작업(공통 리서치·기획·자료)은 `_공통/`에 둔다.
- 그룹 폴더는 input·output 양쪽에 **같은 이름으로 동시에** 존재한다.

### 2. 번호는 그룹 안에서 매긴다

하나의 번호는 input 폴더 1개와 output 폴더 1개를 **동시에** 가리킨다. 두 폴더의 이름은 글자 하나까지 같다. 폴더 목록을 나란히 놓으면 항상 짝이 맞아야 하고, output만 있는 번호는 존재할 수 없다.

- 연번은 **그룹마다 독립**이다. 각 그룹 폴더 안에서 `01`부터 시작한다. 그룹이 다르면 같은 번호가 있어도 된다.
- 다음 번호는 **그 그룹 폴더 안만** 스캔한다. `input_by_human/<그룹>/`과 `output_from_AI/<그룹>/` 양쪽에서 `YYYYMMDD_NN_` 패턴의 최대 `NN`에 1을 더한다. 그룹이 비어 있으면 `01`.
- 그룹 안에서는 번호가 곧 그 갈래의 진행 순서다. 프로젝트 전체 시간순은 번호가 아니라 폴더명 앞의 날짜(`YYYYMMDD`)로 따라간다.
- `_`로 시작하는 **작업 폴더**(`_요청_템플릿/` 등)는 연번에서 제외한다. 단 `_공통/`처럼 `_`로 시작하는 **그룹 폴더** 안의 작업 폴더는 연번에 포함한다.
- **채팅으로 시작한 작업**: 요청 문서가 없더라도 AI는 산출물을 만들기 전에 그룹을 정하고 같은 번호의 input 폴더와 `request.md`를 먼저 만든다. 채팅에서 받은 지시를 요약해 적고, 머리말에 `> 이 요청서는 터미널 세션 지시를 AI가 옮겨 적은 것입니다. (YYYY-MM-DD)`를 붙여 사람이 직접 쓴 요청과 구분한다. 이 규칙 때문에 input과 output의 번호가 어긋나는 일이 없다.
- 사람이 형식을 안 지킨 폴더(예: `새아이디어/`)를 만들어 두어도 된다. AI가 그 작업을 집을 때 그룹을 판정하고 그 그룹의 다음 번호로 `YYYYMMDD_NN_새아이디어`로 정규화한 뒤 진행한다.

### 3. 요청도 산출물도 폴더

요청과 산출물 모두 파일 하나가 아니라 **폴더**다. 요청에 참고 자료를 딸려 보낼 자리를 만들기 위해서다.

- 요청 진입점은 항상 `request.md`, 산출물 진입점은 항상 `00_요약.md`. 이 두 파일명은 고정이다.
- 참고 소스(이미지·CSV·기존 문서 등)는 요청 폴더 안에 자유롭게 넣는다. AI는 작업 시 그 폴더 전체를 입력으로 읽는다.
- `00_요약.md`에는 무엇을 했고, 어떤 파일을 어떤 순서로 보면 되고, 핵심 결론이 무엇인지(3줄)를 적는다. 산출물이 많으면 하위 폴더로 묶되 진입점은 언제나 `00_요약.md` 하나다.

### 4. 완료 시 폴더명 확정

산출물 작성이 끝나면 AI가 주제를 확정해 **input·output 폴더를 같은 이름으로 함께 rename**한다. 요청 시점의 임시 제목이 그대로 남아 나중에 무슨 작업이었는지 모르게 되는 걸 막기 위해서다.

- 형식: `YYYYMMDD_NN_주제` (예: `20260826_01_협업폴더-구조개선`)
  - `YYYYMMDD` — 그 쌍이 **처음 만들어진 날짜**. rename할 때도 바뀌지 않는다.
  - `NN` — 그룹 안에서의 2자리 연번, 그대로 유지.
  - `주제` — 한글 2~5어절을 `-`로 연결. 공백 없이, 40자 이내, `/ \ : * ? " < > |` 금지.
- 작업하다 보니 그룹 판정이 바뀌었으면 rename과 함께 **양쪽 그룹 폴더로 동시에 이동**한다. 이때 번호는 옮겨 간 그룹 기준으로 다시 매긴다.
- rename·이동은 반드시 **쌍으로 동시에**. 한쪽만 바뀐 상태로 작업을 끝내지 않는다.
- rename 후 문서 안에 옛 경로를 참조하는 곳이 있으면 함께 고친다.

### 5. 문서 작성

- 사람이 읽을 문서는 담백하게 쓴다. 불릿·이모지·과장 표현 남발 금지, 결론 먼저.

### 6. AI 작업 공간

- 이 협업 폴더 밖에서는 AI가 프로젝트 내부 구조를 작업하기 편하게 자유롭게 구성해도 된다.
- 단, 그 구조·설계·프로세스에 대한 설명 문서는 작업 폴더 곳곳에 흩뿌리지 말고 해당 요청의 `output_from_AI/<그룹>/<폴더>/` 안에 축적한다.
- 목적: 인간이 이해하지 못하는 파일 난립 방지.

## 사용법

1. `_요청_템플릿/` 폴더를 복사해 `input_by_human/<그룹>/<주제>/`로 만든다. 갈래가 없으면 그룹은 `_공통`.
2. `request.md`를 채우고, 참고 소스를 같은 폴더에 넣는다.
3. AI에게 그 폴더를 가리켜 작업을 요청한다.
4. 완료되면 `output_from_AI/`의 같은 경로 폴더에서 `00_요약.md`부터 읽는다.
