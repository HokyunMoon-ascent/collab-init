# human 지시 사항 및 결과 파일 모음

이 폴더는 이 프로젝트에서 **인간과 AI가 협업하는 단일 인터페이스**다. 인간은 이 폴더만 보면 전체 작업을 파악할 수 있어야 한다.

## 구조

```
human 지시 사항 및 결과 파일 모음/
├── README.md
├── input_by_human/
│   ├── _요청_템플릿/                      # `_` 시작 = 연번 제외
│   │   └── request.md
│   └── 20260826_01_협업폴더-구조개선/
│       ├── request.md                    # 요청 본문 (진입점)
│       └── (참고 소스: 이미지·CSV·기존 문서)
└── output_from_AI/
    └── 20260826_01_협업폴더-구조개선/      # input과 완전히 동일한 폴더명
        ├── 00_요약.md                     # 산출물 진입점
        └── (산출물)
```

## human-AI 협업 규칙 (collab-init v2)

### 1. 번호는 쌍(pair)에 붙는다

하나의 번호는 input 폴더 1개와 output 폴더 1개를 **동시에** 가리킨다. 두 폴더의 이름은 글자 하나까지 같다. 폴더 목록을 나란히 놓으면 항상 짝이 맞아야 하고, output만 있는 번호는 존재할 수 없다.

- 다음 번호는 `input_by_human/`과 `output_from_AI/` **양쪽을 모두** 스캔해 `YYYYMMDD_NN_` 패턴의 최대 `NN`에 1을 더해 정한다. 하나도 없으면 `01`.
- `_`로 시작하는 항목(`_요청_템플릿/` 등)은 연번에서 제외한다.
- **채팅으로 시작한 작업**: 요청 문서가 없더라도 AI는 산출물을 만들기 전에 같은 번호의 input 폴더와 `request.md`를 먼저 만든다. 채팅에서 받은 지시를 요약해 적고, 머리말에 `> 이 요청서는 터미널 세션 지시를 AI가 옮겨 적은 것입니다. (YYYY-MM-DD)`를 붙여 사람이 직접 쓴 요청과 구분한다. 이 규칙 때문에 input과 output의 번호가 어긋나는 일이 없다.
- 사람이 형식을 안 지킨 폴더(예: `새아이디어/`)를 만들어 두어도 된다. AI가 그 작업을 집을 때 `YYYYMMDD_NN_새아이디어`로 정규화한 뒤 진행한다.

### 2. 요청도 산출물도 폴더

요청과 산출물 모두 파일 하나가 아니라 **폴더**다. 요청에 참고 자료를 딸려 보낼 자리를 만들기 위해서다.

- 요청 진입점은 항상 `request.md`, 산출물 진입점은 항상 `00_요약.md`. 이 두 파일명은 고정이다.
- 참고 소스(이미지·CSV·기존 문서 등)는 요청 폴더 안에 자유롭게 넣는다. AI는 작업 시 그 폴더 전체를 입력으로 읽는다.
- `00_요약.md`에는 무엇을 했고, 어떤 파일을 어떤 순서로 보면 되고, 핵심 결론이 무엇인지(3줄)를 적는다. 산출물이 많으면 하위 폴더로 묶되 진입점은 언제나 `00_요약.md` 하나다.

### 3. 완료 시 폴더명 확정

산출물 작성이 끝나면 AI가 주제를 확정해 **input·output 폴더를 같은 이름으로 함께 rename**한다. 요청 시점의 임시 제목이 그대로 남아 나중에 무슨 작업이었는지 모르게 되는 걸 막기 위해서다.

- 형식: `YYYYMMDD_NN_주제` (예: `20260826_01_협업폴더-구조개선`)
  - `YYYYMMDD` — 그 쌍이 **처음 만들어진 날짜**. rename할 때도 바뀌지 않는다.
  - `NN` — 2자리 연번, 그대로 유지.
  - `주제` — 한글 2~5어절을 `-`로 연결. 공백 없이, 40자 이내, `/ \ : * ? " < > |` 금지.
- rename은 반드시 **쌍으로 동시에**. 한쪽만 바뀐 상태로 작업을 끝내지 않는다.
- rename 후 `request.md`·`00_요약.md` 안에 옛 폴더명을 참조하는 경로가 있으면 함께 고친다.

### 4. 문서 작성

- 사람이 읽을 문서는 담백하게 쓴다. 불릿·이모지·과장 표현 남발 금지, 결론 먼저.

### 5. AI 작업 공간

- 이 협업 폴더 밖에서는 AI가 프로젝트 내부 구조를 작업하기 편하게 자유롭게 구성해도 된다.
- 단, 그 구조·설계·프로세스에 대한 설명 문서는 작업 폴더 곳곳에 흩뿌리지 말고 해당 요청의 `output_from_AI/<폴더>/` 안에 축적한다.
- 목적: 인간이 이해하지 못하는 파일 난립 방지.

## 사용법

1. `_요청_템플릿/` 폴더를 복사해 `input_by_human/<주제>/`로 만든다.
2. `request.md`를 채우고, 참고 소스를 같은 폴더에 넣는다.
3. AI에게 그 폴더를 가리켜 작업을 요청한다.
4. 완료되면 `output_from_AI/`의 같은 이름 폴더에서 `00_요약.md`부터 읽는다.
